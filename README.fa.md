# Agent Studio

[English](README.md)

یک اپ گرافیکی که روی کامپیوتر خودت اجرا می‌شود و با آن یک تیم ایجنت هوش مصنوعی روی کدت کار می‌کند. ایجنت‌ها را روشن و خاموش می‌کنی، برای هر کدام حالت انتخاب می‌کنی و کار یا موضوعی به آن‌ها می‌دهی. ایجنت توسعه‌دهنده برنامه‌ریزی می‌کند و می‌سازد، ناظرها وسط کارش نظر می‌دهند، تسترها نتیجه را تست می‌کنند و مشاورها با هم درباره‌ی یک سؤال بحث می‌کنند.

اپ از [Claude](https://claude.com) و [Claude Agent SDK](https://docs.claude.com/en/docs/agent-sdk/overview) استفاده می‌کند. رابط کاربری فارسی و انگلیسی است.

## ایده‌ی اصلی

ایجنت‌ها دو دسته‌اند:

- **دستیار (T):** یک ورودی می‌گیرد، همان کاری را که برایش ساخته شده انجام می‌دهد و خروجی می‌دهد. مثلاً مترجم یا خلاصه‌کننده.
- **متخصص (S):** یک تخصص دارد، مثل بک‌اند، امنیت یا UX، و در حالتی کار می‌کند که تو انتخاب کرده‌ای:

| حالت | کاری که ایجنت می‌کند |
|---|---|
| **توسعه‌دهنده** | بررسی می‌کند و یک نقشه پیشنهاد می‌دهد. تو نقشه را به صورت کلی تأیید می‌کنی، نه خط‌به‌خط، یا تغییر می‌خواهی. بعد می‌سازد. |
| **تستر** | فیچری را که نام برده‌ای از دید تخصص خودش تست می‌کند و گزارش می‌دهد. |
| **ناظر** | کار تو یا یک ایجنت دیگر را بررسی می‌کند و نظر می‌دهد. هیچ فایلی را تغییر نمی‌دهد. |
| **مشاور** | درباره‌ی یک سؤال یا موضوع نظرش را می‌گوید. |

هر ایجنت کلید روشن و خاموش و [اسکیل‌های](#اسکیلها) خودش را دارد.

### اتاق کنترل

صفحه‌ی اصلی اپ است. هر ایجنت یک کارت دارد که کلید روشن و خاموش، حالت، وضعیت (در حال کار یا بیکار) و چند قدم آخرش را نشان می‌دهد. پوشه‌ی پروژه را انتخاب می‌کنی، حالت‌ها را تنظیم می‌کنی و پیام می‌نویسی. قبل از ارسال، یک خط بالای جعبه‌ی پیام می‌گوید چه کسی چه کاری می‌کند.

اینکه چه اتفاقی می‌افتد به ایجنت‌های روشن بستگی دارد، به همین ترتیب:

| اگر… | چه می‌شود |
|---|---|
| پیام با `@اسم` شروع شود | فقط همان ایجنت کار می‌کند. دستیار کارش را انجام می‌دهد؛ متخصص به‌عنوان مشاور جواب می‌دهد و ناظرها نظر می‌دهند. |
| یک توسعه‌دهنده روشن باشد | نقشه می‌دهد ← ناظرها بررسی می‌کنند ← تو تأیید می‌کنی یا تغییر می‌خواهی ← **مرحله‌به‌مرحله** می‌سازد: آخر هر مرحله ناظرها نظر می‌دهند و توسعه‌دهنده قبل از مرحله‌ی بعد نظرشان را اعمال می‌کند ← بررسی نهایی ← تسترها تست می‌کنند. |
| فقط تستر روشن باشد | تست می‌کنند و ناظرها گزارش‌ها را بررسی می‌کنند. |
| یک مشاور | جواب می‌دهد و ناظرها نظر می‌دهند. |
| دو مشاور یا بیشتر | در دو دور بحث می‌کنند: اول هر کدام نظرش را می‌دهد، بعد هر کدام نظر بقیه را می‌خواند و جواب می‌دهد. |
| فقط ناظر | تغییرات ذخیره‌نشده‌ی خودت در پوشه را بررسی می‌کنند. |

هر بار فقط یک ایجنت می‌تواند توسعه‌دهنده باشد. همه‌ی گفتگوها در صفحه‌ی **تاریخچه** می‌مانند و از همان‌جا می‌شود ادامه‌شان داد.

### Agent Studio Code

با دکمه‌ی بالای صفحه، اتاق کنترل به **Agent Studio Code** تبدیل می‌شود و یک پنل تغییرات به آن اضافه می‌شود. هر تغییر کد آنجا با اسم فایل، مسیر و ایجنتی که پیشنهادش داده نمایش داده می‌شود و می‌پرسد انجام شود یا نه:

- ویرایش توسعه‌دهنده تا جواب تو به فایل نمی‌رسد. اگر «نه» بگویی، می‌توانی دلیلش را بنویسی تا ایجنت آن را بخواند و کارش را اصلاح کند.
- تستر، ناظر و مشاور نمی‌توانند فایل را ویرایش کنند، ولی می‌توانند تغییر پیشنهاد بدهند. اگر قبول کنی، خود اپ آن را اعمال می‌کند.

دستورهایی که ایجنت در ترمینال اجرا می‌کند در این پنل نمایش داده نمی‌شوند. به ایجنت‌ها گفته شده فایل‌ها را فقط با ابزار ویرایش تغییر بدهند، ولی یک دستور هم می‌تواند فایلی را عوض کند؛ پس کارت را زیر git نگه دار.

### نتیجه‌ی مشترک

روی دو نتیجه یا بیشتر **انتخاب** را بزن، یا **انتخاب همه‌ی نتایج** را بزن، بعد **بحث و نتیجه‌ی مشترک** را بزن. ایجنت‌هایی که آن نتایج را نوشته‌اند به هم جواب می‌دهند و یکی از آن‌ها نتیجه‌ی مشترک را می‌نویسد. اگر اختلاف واقعی بماند، آن را می‌گوید و یک گزینه را پیشنهاد می‌کند.

## پیش‌نیازها

- [Node.js](https://nodejs.org) نسخه‌ی ۲۰ یا بالاتر
- [PostgreSQL](https://www.postgresql.org/download/) نسخه‌ی ۱۴ یا بالاتر، روی همین کامپیوتر
- دسترسی به Claude: یا [Claude Code](https://docs.claude.com/en/docs/claude-code/overview) که روی همین کامپیوتر لاگین شده باشد، یا یک API key (پایین‌تر توضیح داده شده)
- Git، تا ناظرها ببینند در پروژه چه چیزی تغییر کرده

## راه‌اندازی در ویندوز

1. پروژه را دانلود کن:

</div>

```bash
git clone https://github.com/Eskandarihadi/agent-studio.git
```

<div dir="rtl">

2. در پوشه‌ی `agent-studio` روی **`set-password.cmd`** دوبار کلیک کن و رمز PostgreSQL را بنویس. خودش فایل `.env` را می‌سازد و دیتابیس را آماده می‌کند.
3. روی **`start.cmd`** دوبار کلیک کن. دفعه‌ی اول پکیج‌ها را نصب می‌کند، بعد اپ را اجرا می‌کند و `http://localhost:5180` را در مرورگر باز می‌کند.

برای ساختن شورت‌کات روی دسکتاپ: روی `start.cmd` راست‌کلیک کن ← *Send to* ← *Desktop (create shortcut)*. برای بستن اپ، پنجره‌ی سیاه را ببند.

## وصل شدن به Claude

یکی از این دو راه لازم است:

**الف) لاگین Claude Code (برای استفاده‌ی شخصی).** Claude Code را نصب کن و یک بار لاگین کن:

</div>

```bash
npm install -g @anthropic-ai/claude-code
```

```bash
claude
```

<div dir="rtl">

از آن به بعد Agent Studio از همین لاگین استفاده می‌کند و مصرف ایجنت‌ها از اشتراک Claude خودت کم می‌شود. لاگین شخصی است؛ آن را با دیگران شریک نشو.

**ب) API key.** از [Claude Console](https://console.anthropic.com) یک کلید بساز و در فایل `.env` بگذار:

</div>

```
ANTHROPIC_API_KEY=your-key
```

<div dir="rtl">

اگر کلید تنظیم شده باشد، به‌جای لاگین از آن استفاده می‌شود و هزینه از حساب Console کم می‌شود. اگر کس دیگری غیر از صاحب لاگین از اپ استفاده می‌کند، از این روش استفاده کن.

## نحوه‌ی استفاده

1. **صفحه‌ی ایجنت‌ها:** ایجنت‌هایت را بساز. برای هر کدام تخصص و دستورالعمل بنویس و این‌ها را انتخاب کن:
   - نوع: S یا T
   - ابزارها: هیچ، فقط خواندن، یا خواندن و نوشتن. حالت توسعه‌دهنده «خواندن و نوشتن» لازم دارد.
   - مدل
   - اسکیل‌ها
2. **اتاق کنترل:** پوشه‌ی پروژه را انتخاب کن، ایجنت‌های مورد نظر را روشن کن و حالت هر کدام را تعیین کن.
3. کار یا موضوع را بنویس و **ارسال** را بزن (یا Ctrl+Enter).
4. اگر توسعه‌دهنده نقشه داد، نظر ناظرها را بخوان. بعد **تأیید و ساخت** را بزن، یا بنویس چه چیزی عوض شود.
5. هر وقت خواستی با **توقف** کار ایجنت‌ها را متوقف کن.

نکته‌ها:

- در ریشه‌ی پروژه‌ات فایل `CLAUDE.md` بگذار و پروژه، تکنولوژی‌ها و قوانینش را توضیح بده. همه‌ی ایجنت‌ها اول هر گفتگو آن را می‌خوانند.
- دکمه‌ی **@** روی کارت هر ایجنت، اسمش را اول پیام می‌گذارد تا فقط همان جواب بدهد.
- ایجنت‌ها به همان زبانی جواب می‌دهند که تو می‌نویسی.

## اسکیل‌ها

اسکیل پوشه‌ای است با یک فایل `SKILL.md` که به ایجنت یاد می‌دهد یک کار مشخص را چطور انجام دهد. اسکیل‌ها در یک کتابخانه‌اند و تو انتخاب می‌کنی هر ایجنت کدام‌ها را داشته باشد. هر ایجنت فقط اسکیل‌های خودش را می‌بیند.

در صفحه‌ی **اسکیل‌ها** دو راه داری:
- **نصب از GitHub:** لینک پوشه‌ای را بده که در ریشه‌اش `SKILL.md` دارد، مثلاً `https://github.com/anthropics/skills/tree/main/skills/pdf`. قبل از نصب، محتوای اسکیل و لیست فایل‌هایش را می‌بینی.
- **نوشتن اسکیل:** خودت `SKILL.md` را بنویس.

بعد در صفحه‌ی **ایجنت‌ها**، ایجنت را ویرایش کن و تیک اسکیل‌هایش را بزن.

> اسکیل‌ها می‌توانند اسکریپت داشته باشند که ایجنت روی کامپیوترت اجرا کند. قبل از نصب، اسکیل را بخوان و فقط از منبع مطمئن نصب کن.

## انتقال به کامپیوتر دیگر

کد در همین ریپو است، ولی داده‌های خودت در آن نیستند:
- ایجنت‌ها و گفتگوها در دیتابیس PostgreSQL هستند.
- اسکیل‌های نصب‌شده در پوشه‌ی `data/` هستند.

برای انتقال، پوشه‌ی `data/` را کپی کن و از دیتابیس خروجی بگیر:

</div>

```bash
pg_dump -U postgres -d agent_studio -f agent_studio.sql
```

<div dir="rtl">

روی کامپیوتر جدید، بعد از `npm run db:setup`:

</div>

```bash
psql -U postgres -d agent_studio -f agent_studio.sql
```

## امنیت

ایجنت در حالت توسعه‌دهنده می‌تواند در پوشه‌ی پروژه فایل‌ها را تغییر بدهد و دستور اجرا کند. برای همین:

- اپ فقط روی کامپیوتر خودت باز می‌شود (`127.0.0.1`) و از بقیه‌ی شبکه در دسترس نیست. آن را روی اینترنت نگذار، چون لاگین ندارد.
- دستورهای خطرناک مثل `git push`، `git reset --hard` و `rm -rf` برای ایجنت‌ها بسته‌اند.
- تستر، ناظر و مشاور نمی‌توانند فایل‌ها را تغییر بدهند.
- در پوشه‌ای کار کن که git دارد، تا بتوانی تغییرات ایجنت را ببینی و برگردانی.
- فایل `.env` رمز دیتابیس را دارد و هیچ‌وقت commit نمی‌شود.

## رفع مشکل

| مشکل | راه‌حل |
|---|---|
| `password authentication failed` | رمز داخل `.env` اشتباه است یا ذخیره نشده. دوباره `set-password.cmd` را اجرا کن. |
| `DATABASE_URL is missing` | فایل `.env.example` را به `.env` کپی کن و پرش کن. |
| ایجنت‌ها خطای احراز هویت می‌دهند | یک بار با دستور `claude` لاگین کن، یا `ANTHROPIC_API_KEY` را در `.env` بگذار. |
| `GitHub rate limit reached` موقع نصب اسکیل | یک ساعت صبر کن، یا `GITHUB_TOKEN` را در `.env` بگذار. |
